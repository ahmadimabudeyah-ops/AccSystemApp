# FSD-1: المشتريات والموردون (Procure-to-Pay)

## 1. نموذج العملية
طلب (draft→approved) → أمر (confirmed) → استلام (يرفع المخزون + متوسط التكلفة)
→ فاتورة (مطابقة ثلاثية: كمية/سعر مقابل الأمر والاستلام) → ترحيل → دفعة →
تخصيص → إغلاق. المرتجع يخفض المخزون ويولد إشعارًا.

## 2. البيانات الرئيسية
المورد (طرف + شروط دفع + حد ائتماني)، الصنف (حساب مخزون/مصروف)، المستودع/الموقع،
شروط الدفع، الضرائب (مشتريات قابلة للاسترداد حسب Fiscal Position).

## 3. المستندات والحالات
- طلب: draft/approved/cancelled (الاعتماد إجباري فوق حد يُضبط).
- أمر: draft/confirmed/partially_received/fully_received/cancelled.
- استلام: draft/confirmed (التأكيد يرحّل مخزنيًا ولا رجوع).
- فاتورة: draft/posted/partially_paid/paid (المجمدة تتحصّل فقط).
- دفعة: draft/confirmed/posted + تخصيصات UQ(payment,bill).

## 4. المطابقة الثلاثية
كمية الفاتورة ≤ المستلم − المفوتر سابقًا، والسعر ضمن تسامح ±2% من الأمر
(يُضبط)، وإلا تُعلق الفاتورة `disputed` (حالة تُضاف مرحلة 2).

## 5. مصفوفة الترحيل

| الحدث | مدين | دائن |
|---|---|---|
| ترحيل فاتورة | مخزون 1310 (أو حساب السطر) | مورد 2010 |
| ضريبة مشتريات | ضريبة مستردة (حساب الضريبة) | مورد 2010 |
| ترحيل دفعة | مورد 2010 | نقدية/بنك |
| مرتجع مورد | مورد 2010 | مخزون |

## 6. قواعد العمل (مقتطف ملزم، كاملة PR001–PR100 في الملحق)

- PR001: لا أمر بلا مورد نشط.
- PR002: لا استلام بلا موقع تخزين صالح.
- PR010: الاستلام المؤكد يرفع `stock_quants` ويعيد المتوسط المرجح.
- PR020: الفاتورة المرحلة لا تُعدل ماليًا (مسموح التحصيل فقط).
- PR030: التخصيص لا يتجاوز min(حر الدفعة، متبقي الفاتورة).
- PR040: الدفعة تُرحّل بحساب نقدي صريح من الطلب.

## 7. الاختبارات (PT01–PT30، مقتطف)

- PT01 إنشاء طلب واعتماده. PT05 استلام يرفع الرصيد والمتوسط.
- PT10 فاتورة بكمية زائدة عن المستلم → رفض. PT15 ترحيل مزدوج بنفس المفتاح → قيد واحد.
- PT20 تخصيص زائد → 409. PT25 إغلاق الفترة يمنع ترحيل فاتورة بتاريخها.
